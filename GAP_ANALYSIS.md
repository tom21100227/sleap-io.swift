# GAP_ANALYSIS.md — sleap-io.swift vs. upstream

**Date:** 2026-06-10
**Compares:** `sleap-io.swift` (this repo, ~Phase 4 / v0.3.x) against
[`talmolab/sleap-io`](https://github.com/talmolab/sleap-io) (Python, reference)
and [`talmolab/sleap-io.js`](https://github.com/talmolab/sleap-io.js) (v0.4.0),
weighted by the needs of the downstream SwiftUI app
[`sleap.swift`](../sleap.swift) (the native sleap-label replacement) and a future
`sleap.swift` training/inference backend.

> **North star:** unblock the native SwiftUI annotation GUI on macOS + iPadOS.
> Gaps are prioritized by `guiRelevance` first, `backendRelevance` second.

- Raw machine-readable inventory: [`docs/gap-analysis/gaps_raw.json`](docs/gap-analysis/gaps_raw.json) (328 gaps, structured)
- Per-module narrative summaries: [`docs/gap-analysis/module_summaries.md`](docs/gap-analysis/module_summaries.md)
- The execution plan derived from this: [`MEGA_PLAN.md`](MEGA_PLAN.md)

## 1. Executive summary

A 14-agent parity audit compared every model type, codec, I/O path, renderer, and
transform across the three implementations. Headline numbers:

| Metric | Count |
|---|---:|
| Total gaps catalogued | **328** |
| `swiftStatus: none` (entirely absent) | 208 |
| `swiftStatus: partial` (exists but diverges/incomplete) | 116 |
| `swiftStatus: full` (notable parity) | 4 |
| **High GUI relevance** | **85** |
| High backend relevance | 51 |
| Effort: S / M / L / XL | 117 / 114 / 73 / 24 |

**The Swift port is a strong foundation but a thin one.** Read/write of the SLP
1.0–1.5 core, the lazy column store, the identity model, embedded video, and the
Phase 3–4 codecs all work. What's missing is the *breadth* of behavioral API that
Python (4.0k-line `labels.py`) and JS expose — the methods a GUI calls on every
edit, and the array/tensor surface a training backend needs.

**Three findings rise above "missing feature" to "correctness bug":**

1. **`provenance` is `[String: String]`** but upstream is `dict[str, Any]`. Any
   `.slp` with numeric/nested provenance (model paths, hyperparameters,
   `cellpose_diameter=30`) **silently loses data on read and cannot round-trip on
   write** — across every codec. This is data corruption, not a missing feature.
2. **SLP format is hard-capped at 1.5** (`kMaxSupportedFormatVersion`); current
   Python writes 1.9 / 2.0 / 2.1 / 2.3 / 2.4 routinely. We throw
   `formatVersionTooNew` on most modern projects — **we cannot open files SLEAP
   produces today.**
3. **Several codecs read/write the wrong on-disk schema entirely** and cannot
   interoperate with real upstream files: AlphaTracker (invented schema),
   AnalysisHDF5 (`locations` vs real `tracks` + MATLAB axis preset), JABS (ignores
   pose-version model + y/x flip), Label Studio (`parentID` vs `relation`), CSV
   (long-table vs pandas family). These pass our own round-trip tests but fail
   against files generated by Python/JS.

## 2. GUI-readiness findings (from `sleap.swift`)

`sleap.swift` pins this package at revision `96341ef` and consumes all four
products (`SleapIO`, `SleapHDF5`, `SleapVideo`, `SleapRendering`). Its `PLAN.md`,
`AGENTS.md`, and in-code TODOs name the data-layer blockers directly:

| GUI need | Source | Gap in sleap-io.swift | Priority |
|---|---|---|---|
| O(1) frame lookup that doesn't materialize | `FrameIndex.build()` blocker | `Labels.frame(for:at:)` is O(n); no cached index. `frameMetadata()` now exists (partial fix). | **High** |
| Persistent video relocation | `VideoRelocator.swift` TODO + `HDF5_IPADOS_STRATEGY.md` | No `Video.replaceFilename` / `Labels.replaceFilenames` / `match_video` / `open_videos=defer`; iPad needs security-scoped bookmarks. | **High** |
| Safe save snapshot | `PLAN.md` "Save Isolation" | `Labels` has no deep-copy/`copy()`; save gates edits with an `isSaving` flag instead of a real snapshot. | **High** |
| SwiftUI change propagation | `AGENTS.md` rule #5 | Reference mutation needs manual `project.revision` bumping; no `@Observable`/Combine/change-notification, no stable `Identifiable`/`Hashable`. | **High** |
| Smooth scrubbing | `PLAN.md` blocker #3 | `AVFoundationBackend.prefetch()` is a no-op. | Medium |
| Recoverable error UX | audit cross-cutting | `SleapIOError` has 8 coarse string cases; no `ErrorMode`, no skeleton-mismatch/missing-video typed recovery. | **High** |
| Progress + cancellation | audit cross-cutting | `load`/`save` are opaque awaits — only an indeterminate spinner, no cancel. | **High** |
| Coordinate convention | audit cross-cutting | pixel-center / 0.5-offset / y-down / NaN-as-invisible are implicit and scattered; a SwiftUI `Canvas` overlay must agree or every annotation mirrors. | **High** (cheap) |
| iPad packaging | `HDF5_IPADOS_STRATEGY.md` | **Largely solved** — package now vendors `CHDF5.xcframework` (Option A). Remaining work is downstream validation + relocation API. | — |

Phase 4 of `sleap.swift` (next up) additionally wants: track-color rendering
(`color_by="track"`), QC overlays, batch ops (bulk track assign / clear
predictions), and a Metal path for 100+ instances — all of which map to renderer
and `Labels`/`LabeledFrame` gaps below.

## 3. Per-module parity (narrative)

Full text in [`module_summaries.md`](docs/gap-analysis/module_summaries.md). One-line
takeaways, ordered by GUI impact:

1. **Labels API (38 gaps)** — thin container. Missing O(1) `get_frame`/`reindex`,
   rich `__getitem__`/`find` with foreign-video resolution, `clean`,
   `remove_predictions`, `copy`, annotation query families
   (`get_rois`/`get_masks`/`get_bboxes`/`get_centroids`), counts
   (`n_user_instances`…), and the whole `numpy`/`from_numpy`/`split` surface.
2. **Instance / Frame / Point (39 gaps)** — missing `numpy()`, `n_visible`,
   `is_empty`, `centroid_xy`, `bounding_box`, `update_skeleton`,
   `replace_skeleton`, `from_numpy`/`empty`; `LabeledFrame.merge` is a stub with no
   spatial matching / conflict return. No `Centroid` / `BoundingBox` / `Identity` /
   `Instance3D` types.
3. **Skeleton / Video (34 gaps)** — Skeleton mutation is good, but derived
   accessors (`node_names`, `edge_inds`, `symmetry_inds`, `get_flipped_node_inds`,
   `require_node`, `reorder_nodes`, `match_nodes`) are absent. `SkeletonCodec`
   diverges from Python's jsonpickle SLP encoder (round-trip risk). `Video` lacks
   `shape`/`grayscale`/`exists`/`open`/`replace_filename`/`fps`/`matches_*`.
4. **ROI / Mask / LabelImage / Matching (18 gaps)** — weakest area. The **entire
   ~1900-LOC matching/merge subsystem is absent** (proofreading is blocked).
   `LabelImage` absent. ROI/mask are simplified single-structs (no WKB/geometry).
5. **SLP HDF5 (23 gaps)** — solid 1.0–1.5 core, but format cap at 1.5; no
   bboxes/centroids/identities/label_images/video_crops datasets; bespoke
   sessions schema; no embed-on-save pipeline; lossy provenance.
6. **Codecs COCO/CSV/LS/AT (21)** & **DLC/JABS/YOLO/Analysis (23)** — see §1 finding
   3; multiple wrong-schema codecs.
7. **Rendering (19 gaps)** — minimal CG renderer; no `color_by="track"`, marker
   shapes, overlays (mask/roi/bbox/centroid — *models exist but aren't drawn*),
   trails, callbacks, or `render_image`/`render_video` entry points.
8. **Transforms (19 gaps)** — has affine toolkit + Instance helpers; no unified
   `Transform`, flip/pad, crop-offset, frame/video pipeline, OOB masking.
9. **Video backends (20 gaps)** — three read paths OK; no grayscale autodetect,
   no SEQ/TIFF, no crop backend, no raw-array frame output, no writer.
10. **Dispatch / CLI (28 gaps)** — `Labels.load/save` covers 9 formats + sniff; CLI
    has 3 of 18 `sio` commands; no return polymorphism (Labels-only), no
    `load_video`/`load_skeleton`/`load_labels_set`.
11. **Cross-cutting (16 critic gaps)** — public umbrella API, provenance typing,
    camera calibration math, remote/URL loading, version constant, concurrency
    contract, observable model layer, identity-interning on decode.
12. **Missing formats (13 gaps)** — GeoJSON + TrackMate + TIFF label-images are in
    JS (in scope); SEQ is Python-only (in scope for neuroscience inputs); NWB +
    LEAP depend on the Python/h5py ecosystem and remain **out of scope** (confirms
    CLAUDE.md Phase 5).

## 4. Top GUI-unblocking gaps (the implementation focus)

Ordered roughly by leverage-per-effort for the GUI. These seed Milestones M1–M2 in
[`MEGA_PLAN.md`](MEGA_PLAN.md).

**Additive, low-regression accessors (mostly S/M, no schema change):**
- `Instance.numpy(invisibleAsNaN:)`, `n_visible`, `is_empty`, `centroid_xy`, `bounding_box`
- `LabeledFrame.numpy()`, `remove_empty_instances`, `remove_predictions`, `is_user_labeled`, `unused_predictions`
- `Skeleton.node_names`, `edge_inds`, `edge_names`, `symmetry_inds`, `get_flipped_node_inds`, `require_node`, `reorder_nodes`, `match_nodes`
- `Video.shape`, `grayscale`, `exists`, `fps`, `frame_to_seconds`/`seconds_to_frame`, `matches_path`
- `Labels` counts (`n_user_instances`, `n_pred_instances`, `n_frames_per_video`, `n_instances_per_track`), `get_track_annotations`
- Coordinate-convention doc + a single `CoordinateConventions` reference (cheap, prevents mirror bugs)
- `SleapIO.version` constant + provenance stamping

**Structural GUI enablers (M/L):**
- O(1) frame/track index inside `Labels` (`get_frame`, `reindex`) — fixes the known O(n) issue
- Rich `Labels` subscripts + `find(video:frameIdx:)` with foreign-video resolution
- `Labels.copy()` deep snapshot (safe save + undo)
- `Labels.clean`, `remove_predictions`
- `Instance.update_skeleton` / `replace_skeleton` (skeleton editing already in the GUI)
- `Video` relocation: `replace_filename`, `Labels.replace_filenames`/`replace_videos`/`add_video`/`match_video`, `open_videos` deferral, security-scoped bookmarks
- Error taxonomy + `ErrorMode`; progress-callback + cancellation contract
- `@Observable`-friendliness / change-notification + stable `Identifiable`/`Hashable`

**Proofreading (L/XL, M2):**
- Matching subsystem (`SkeletonMatcher`/`InstanceMatcher`/`TrackMatcher`/`VideoMatcher` + method enums + `Instance.same_pose_as`/`overlaps_with`)
- Real `LabeledFrame.merge` cascade + `Labels.merge` → `MergeResult`/`MatchResult`/conflicts/`merge_history`

## 5. Top backend (training/inference) gaps

For a future `sleap.swift` backend (lower priority than GUI, but cheap wins):
- `Labels.numpy`/`from_numpy`/`update_from_numpy` (fix the two `TensorCodec` axis/track-slot bugs first)
- `Instance`/`PredictedInstance`/`LabeledFrame` `numpy`/`from_numpy` with scores
- `to_analysis_arrays` builder (occupancy/locations/scores) + `LazyDataStore` fast numpy path
- `split` / `make_training_splits` / `LabelsSet`
- `Transform` pipeline with NaN-preserving `apply_to_points`, OOB masking

## 6. Confirmed out of scope (Apple-native)

- **NWB** (`pynwb`/`ndx-pose`/`ndx-multisubjects`) and **LEAP `.mat`** (`pymatreader`)
  — no Swift ecosystem; matches CLAUDE.md Phase 5. Track as `wontfix`/future.
- **Remote/Google-Drive loading** (`io/_remote.py`, `io/_gdrive.py`) — deferred;
  `URLSession` range requests make a future minimal version feasible but it's not a
  GUI blocker.
- **`sio` video-pipeline CLI** (`trim`/`reencode`/`transform`/`apply-crops`) — needs
  an `AVAssetWriter` encode pipeline; deferred.
